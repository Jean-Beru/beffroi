# Conformance suite

The OpenID Foundation conformance suite is the external judge of spike 1. It runs locally from the prebuilt images of `registry.gitlab.com/openid/conformance-suite`, pinned by version in `compose.yaml`.

```bash
castor start --conformance
castor logs conformance-server
```

Then open https://localhost:8443 (self-signed certificate of the suite's nginx).

## How the suite reaches the OP

- The `op` service has the network alias `op.localhost`, so the suite container resolves it like your browser does.
- Caddy issues the OP certificate from its internal CA. The suite container starts with `tests/conformance/server-entrypoint.sh`, which imports that CA into the JVM truststore before launching the suite exactly as the upstream image does. Everything else in the entrypoint is the upstream command line.
- Verified: a Java `HttpsURLConnection` from the suite container to `https://op.localhost` completes the TLS handshake.

## Gotchas met while wiring it

- The MongoDB property of the jar is `spring.data.mongodb.uri`.
- `SPRING_PROFILES_ACTIVE=dev` avoids the suite login, but the Google and GitLab OAuth registrations must be non-empty placeholders or Spring refuses to start. This mirrors the official `docker-compose-prebuilt.yml`.
- The nginx image proxies to `http://server:8080`: the server service needs the network alias `server`.
- The scripted browser of the suite runs inside the server JVM and follows the OP's redirect to `https://localhost:8443/...`, which is the container itself: the `conformance-redirector` sidecar (socat, same network namespace) forwards that loopback port to nginx, and the entrypoint imports the self-signed certificate of nginx into the JVM truststore next to the Caddy CA.
- An empty `POST` to `/api/runner` must not be sent as a form: Spring answers 415 to `application/x-www-form-urlencoded`, which Symfony's HttpClient adds by default.

## The test plan of spike 1

`oidcc-basic-certification-test-plan`, created with `server_metadata=discovery` and `client_registration=static_client`. Its modules carry their own variant: all `client_secret_basic` except `oidcc-server-client-secret-post`, all `response_type=code` and `response_mode=default`. The plan needs three registered clients: `client` and `client2` in `client_secret_basic` (the second is the wrong client of some modules) and a `client_secret_post` one, because a client authenticates with the one method it registered.

The clients are registered in `apps/op/config/packages/heidi.yaml` (development only): `conformance-basic`, `conformance-basic-second` and `conformance-post`, all three with `requires_pkce: false`, the named exception of decision 0008 of the design repository: the Basic OP profile sends no `code_challenge` (one module out of thirty-five does, and it passes with the exception in place, since a challenge the client sends is verified all the same). Their secrets are generated by `castor provision` into `apps/op/.env.local` (`CONFORMANCE_BASIC_SECRET`, `CONFORMANCE_BASIC_SECOND_SECRET`, `CONFORMANCE_POST_SECRET`). The plan must use the alias `heidi`: the registered redirect URI is `https://localhost:8443/test/a/heidi/callback` and the post-logout one `https://localhost:8443/test/a/heidi/post_logout_redirect`. The user to sign in with is `alice`, password `HEIDI_DEV_USER_PASSWORD` of the same file.

`castor conformance` runs the plan: it fills the placeholders of `tests/conformance/basic-op.json` from those values, creates the plan through the API of the suite, runs every module (or those named by `--module`, a repeatable substring) and prints one result per module with the failures and warnings of its log, then a summary with the suite version and the URL of the plan page. The scripted browser of the suite signs in and consents by itself, following the `browser` section of the configuration; see `tests/conformance/README.md` for how it reaches the OP and the callback of the suite from inside its container.

Certification itself (the right to display the mark, the public listing) is submitted on https://www.certification.openid.net/ and is paid; testing there is free but needs an OP reachable from the Internet. `castor conformance --suite https://www.certification.openid.net` with `CONFORMANCE_TOKEN` in the environment runs the same plan there.
